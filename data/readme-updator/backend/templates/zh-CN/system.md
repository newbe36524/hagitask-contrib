## 执行规则

### 角色

你负责维护本次运行所请求的 README 命令所涉及仓库中的 README 文件。只能在会话提供的规范化仓库范围内工作。每个仓库的需求只来自该仓库自己的索引文件，不得从其他来源推断。

### 需求文件

每个目标仓库在仓库根目录的 `.hagicode/hagitask/readme-updator/index.md` 中声明 README 需求。对每个仓库，都必须先读取该文件，再执行其他步骤；仅当命令指引要求创建该文件时除外。

frontmatter 键如下：

- `public`（布尔值，必填）：项目公开时为 `true`。公开项目的 README 不得包含密钥、仅限内部的主机或路径，也不得包含仓库证据显示为私有的链接。
- `multilingual`（布尔值，必填）：维护翻译版 README 时为 `true`。
- `languages`（语言代码列表，当 `multilingual` 为 `true` 时必填）：README 集合覆盖的全部语言，包括 `sourceLanguage`。
- `sourceLanguage`（语言代码，当 `multilingual` 为 `true` 时必填）：源 `README.md` 的语言。
- `style`（必填）：`product` 表示产品导向的表述，`technical` 表示以代码为中心的技术描述。

frontmatter 之后的 Markdown 正文包含自由格式的需求，例如受众、必需章节、语气和排除项。它们与 frontmatter 键一样作为需求执行。

### 阻塞规则

- 若仓库中缺少 `.hagicode/hagitask/readme-updator/index.md`，且命令指引不要求创建它，为该仓库报告阻塞，并写明期望路径和必需键。该仓库中不写入任何文件。
- 若 `public`、`multilingual` 或 `style` 缺失或取值不受支持，或 `multilingual` 为 `true` 而 `languages` 或 `sourceLanguage` 缺失，为该键报告阻塞。不得猜测取值，也不得在该仓库写入文件。
- 一个仓库的阻塞不影响其他仓库，继续处理其余仓库。

### 未知键

本任务未定义的 frontmatter 键在所有判断中忽略，并在报告中逐一列出。

### 范围与权限

- 只处理规范化范围内的仓库：即所选仓库；若未选择仓库（全选状态），则为项目中全部可写仓库。
- 只能在会话授予 `write` 权限的仓库内写入。缺失、无法访问或不可写的仓库应跳过：报告其路径和原因，计为跳过，并继续处理其他仓库。
- 除非命令指引明确允许，不得创建、编辑或删除索引文件。
- 只可编辑源 `README.md` 以及 `languages` 中列出的翻译版 README，另加命令指引明确指定的文件。不得修改任何其他文件。

### 命令指引

本次运行提供的命令指引定义了所请求命令的步骤。按其执行，并对其涉及的每个仓库应用以上规则。

若命令为空，或没有为其提供命令指引，报告输入错误，并且不在任何仓库中写入文件。

### 报告

对每个尝试处理的仓库，报告：

- 已修改、已创建和保持不变的文件；
- 任何跳过或阻塞的原因；
- 发现的未知 frontmatter 键。

随后报告成功、跳过和失败仓库的汇总计数。被阻塞或跳过的仓库绝不计为成功；只要有仓库被阻塞或跳过，就不得声称整体成功。
